# Orbit 功能、云端积分与 AI 架构

> 当前发布口径：2026-09-14。Orbit 的默认 AI 服务为「Orbit 账号 + 云端积分」；用户自带 API Key（BYOK）仅是高级设置的可选路径，不能作为普通用户的必经步骤。

## 1. 产品边界

Orbit 不替代 Apple 日历，而是把文字、语音转写或日程图片变成可核对的结构化日程，并由用户确认后写入系统日历。

- 日程与循环日程：写入用户选定的 Apple 系统日历；
- 习惯：写入 Apple 提醒事项，可重复、可完成；
- 提醒：由日历提醒、提醒事项或 Orbit 本地通知分别承担；
- 冲突处理：Orbit 只提示冲突和候选空档，绝不自动移动用户已有事件；
- 协作：继续使用 iCloud、Google、Exchange 等用户已有的共享日历，不自建团队日历。

## 2. 已实现的主要能力

| 能力 | 当前行为 | 发布前仍需真机验收 |
|---|---|---|
| 文字、语音、图片录入 | AI 将输入解析为可编辑的日程卡片 | 各输入类型的网络失败、取消和权限拒绝 |
| 日历写入与编辑 | 写入 Apple 日历；支持日期、时间、目标日历、提醒、循环和完整编辑 | 完全访问权限、跨日/全天/循环规则 |
| 习惯与系统提醒事项 | 循环习惯写入 Apple 提醒事项 | 提醒事项完全访问权限、删除和完成状态 |
| 冲突识别与重排建议 | 写入前检查冲突，并给出可选空档 | 多日历、循环事件与时区边界 |
| 今日页、消息与晨晚报 | 展示日程、通知和简报；天气为经许可后的增强信息 | 通知授权、定时投递、无天气时的降级 |
| 快捷指令和 Widget | 提供快速进入/记录入口 | 正式签名下的 App Group 与刷新行为 |
| Orbit 账户与积分 | 注册、登录、积分余额、消耗型积分购买接口及后端账本已接入 | 正式后端部署、StoreKit 沙盒/生产回执和退款链路 |

## 3. 默认云端积分路径

```text
iPhone App
  ├─ 注册 / 登录 Orbit 账户
  ├─ 读取余额、购买积分（Apple StoreKit）
  └─ 发送 AI 请求
          ↓ HTTPS + 用户短期令牌
Orbit 后端
  ├─ 校验账户、积分、限流与输入大小
  ├─ 记录最小化的用量与交易账本
  └─ 发放受限的 OneAPI 调用令牌
          ↓
模型网关 / 模型供应商
          ↓
结构化日程建议 → App 供用户确认 → Apple 日历
```

关键原则：模型供应商的主密钥只保存在服务端的密钥环境中，绝不放进 IPA、Git 仓库、截图或 CI 日志。积分包是 App 内消费的数字服务，正式发布时使用 Apple 消耗型内购；审核账号由后台预置测试积分，不要求审核员购买。

### 积分定义与账本

- 产品：`points50`、`points250`、`points600` 为消耗型积分包；最终售价和积分数在 App Store Connect 定稿后同步配置。
- 扣费时机：只在服务端确认模型请求可执行时扣减；失败、超时或退款应具备幂等处理与可追溯交易记录。
- 额度控制：服务端限制用户余额、单次图片/文本大小、模型白名单、速率和每日预算，避免成本失控。
- 审核与支持：为 App Review 创建独立审核账户并预置积分；不得把真实用户密码、模型 Key 或生产管理令牌写进仓库。

## 4. 高级可选：BYOK

BYOK（Bring Your Own Key）是高级用户自带模型 API Key。该 Key 仅保存在该 iPhone 的 Keychain，并直接请求用户选择的服务商。它适合开发者或明确希望自管模型账单的用户。

BYOK 不是默认入口，也不能用于绕开 Orbit 云端积分所提供的数字服务。面向普通用户的帮助、商店文案、审核路径和首次教学均以 Orbit 云端积分为主。

## 5. 隐私与数据最小化

- 日历、提醒事项和本地对话数据优先留在设备；iCloud 同步仅在用户启用后发生。
- 使用 Orbit 云端 AI 时，输入的文字、语音转写文字或图片会经 Orbit 服务发送给受限模型网关以完成识别；账户标识、交易信息和用量账本由 Orbit 后端处理。
- 不含广告、IDFA 或第三方行为追踪 SDK。
- 正式隐私政策和 App Store 隐私标签必须如实披露账户、购买、用户内容及可能的粗略位置用途；在后端部署后做一次逐项复核。

## 6. v1 不做的事

- 不自动拨打电话。iOS 不能允许 App 静默外呼；电话提醒涉及通信、同意与反骚扰合规。
- 不自动改写用户现有日程，也不自动向他人发送预约消息。
- 不自建另一套日历或待办数据库来替代用户现有系统。

## 7. 发布前的验证顺序

1. 将代码、后端、隐私清单和上架材料提交到 `codex/test`，由 GitHub Actions 构建；
2. 部署正式 Orbit 后端，配置服务端密钥、HTTPS、备份、日志脱敏、预算与告警；
3. 在 App Store Connect 创建三项消耗型积分内购，并在 StoreKit 沙盒完成购买、恢复（若适用）、重复回执、退款和余额验收；
4. 用真机完成日历、提醒事项、通知、语音、照片、网络失败和注销/删除账号流程的验收；
5. 创建独立审核账号和预置积分，填入 ASC 审核备注；
6. 以隐私政策、支持页、App Store 元数据和实际网络行为四方一致为准，提交 TestFlight，再提交审核。
